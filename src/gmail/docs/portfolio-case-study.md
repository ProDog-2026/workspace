# ProDog 포트폴리오 사례 초안

작성일: 2026-10-08  
공개 전 확인: 팀 기여 범위·공개 가능한 코드와 화면·실험 수치

## 한 문장

**Gmail 메일을 안전하게 수집해 AI 요약·프롬프트 인젝션 탐지에 넘기는 로컬 모듈을 구현하고, 최종 위험 판정에 Jev가 필요한지 검증할 비교 기준을 세웠다.**

## 문제

AI가 메일을 요약할 때 메일 본문은 외부 사람이 작성한 자료다. 여기에 AI에게 다른 행동을 요구하는 문구가 숨어 있으면 요약 결과나 후속 동작이 영향을 받을 수 있다. ProDog는 메일을 가져와 요약·정리하고, 수상한 지시를 찾아 사용자에게 근거를 보여주는 서비스를 목표로 한다.

## 내 역할과 구현

나는 팀의 Gmail 연결과 메일 불러오기를 담당했다. Python·FastAPI로 읽기 전용 Google OAuth 흐름을 만들고 Gmail API에서 목록과 본문을 가져왔다. MIME의 일반 텍스트와 HTML 원문을 분석 입력으로 추출하면서 숨김 문구·HTML 주석을 놓치지 않도록 했다. Google 토큰은 암호화해 로컬 SQLite에 보관했고, 세션·CSRF 검사와 계정별 접근 경계를 구현했다. 메일 본문과 RAW는 DB에 저장하지 않으며 제목·발신자 등 일부 메타데이터는 저장한다.

로컬 합성 메일 데모 뒤 실제 Google 계정에서 받은편지함 20개, 본문 1건, 다음 페이지 20개, 토큰 갱신, 익명 세션 차단을 확인했다. 당시 검증은 Python 테스트 99개와 프런트엔드 DOM 테스트 10개를 포함했다. 상세 조건과 미검증 항목은 [검증 기록](verification.md)에 있다.

## 설계에서 중요했던 선택

- 읽기 전용 Gmail 권한만 요청했다. 지금 코드는 메일을 격리·삭제하거나 다른 AI 제품의 읽기를 차단하지 않는다.
- 메일 본문은 저장하지 않되, 분석에 필요한 원문·본문 해시·수집 경고를 후속 모듈에 전달한다.
- 첨부 미분석이나 잘린 입력을 “안전”으로 바꾸지 않고 별도로 표시한다.
- 요약 모델과 최종 위험 판정 모델의 역할을 분리했다. Jev는 요약문 생성이 아니라 **정해진 선택지의 판단** 후보로 검토한다.

## 비교 실험

교수님 피드백에 따라 최종 판정 방식을 **코드 규칙 vs 공식 Jev vs 로컬 OpenJev 계열**로 비교하도록 [실험 보고서](jev-comparison-report.md)를 작성했다. 같은 합성 메일과 동일한 탐지 결과를 입력하고 공격을 놓친 건수, 정상 메일 오경고, 판정 실패, 처리 시간, 외부 데이터 전송을 비교한다.

**현재 단계:** 비교 설계와 문헌 검토까지 끝냈다. Jev 호출·성능 실험 결과는 아직 없다. 실측 전 포트폴리오에서 “Jev로 탐지 성능 향상” 또는 “실서비스 차단 구현”이라고 주장하지 않는다.

## 다음에 넣을 증거

1. 공개 가능한 데모 화면 또는 합성 메일 시연 영상
2. 팀과 합의한 수집 → 탐지 → 판단 → 화면의 데이터 계약
3. 동일 데이터로 실행한 규칙·Jev·OpenJev 결과표와 대표적인 오탐·미탐
4. 결과를 보고 바꾼 설계 한 가지와 그 이유

개인 Gmail 주소·본문, OAuth 비밀값·토큰, 팀원이 공개 동의하지 않은 코드·성과는 포트폴리오에 넣지 않는다.
