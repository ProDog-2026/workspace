# Supabase 대시보드 구현 계획

**Goal:** Supabase Auth 사용자 자신의 `scans` 행을 읽어 목록·상세·일별 그래프에 표시한다.

**Architecture:** 기존 React 화면과 Gmail 수집 기능을 재사용한다. 대시보드는 Supabase 조회 전용으로 바꾸고 기존 Gmail 수집·실험은 명시적인 로컬 화면으로 유지한다. 앱 로그인과 로컬 Gmail 연결의 사용자 귀속을 임의로 같다고 취급하지 않는다.

**Tech Stack:** React/Vite, 공식 supabase-js, 기존 node:test.

**Spec:** 사용자가 제시한 #14 및 대시보드·로그인 완료 조건, `arch/SUPABASE_TABLE.md`.

## 제약과 검증

- 브라우저 DB 호출은 `scans` SELECT만 한다. anon 키만 사용하고 서비스 키는 거절한다.
- RLS가 기본 보안 경계다. 추가 `user_id` 필터를 사용하고 계정 변경 시 이전 화면·조회 요청을 폐기한다.
- 위험·의심 판정을 먼저 표시하고 불완전 안내를 함께 보인다. 미판정은 검사 전이며 실패를 정상으로 바꾸지 않는다.
- evidence는 React 텍스트로 표시한다. 서버가 주지 않은 점수 임계값을 꾸며 표시하지 않는다.
- 페이지 단위 조회임을 그래프에 명시하고 조회 오류를 빈 정상 결과로 바꾸지 않는다.
- 기존 서버의 Supabase 저장·소유권 어댑터는 이 프론트 작업에 포함하지 않으며 완료됐다고 표시하지 않는다.

## 결과와 남은 외부 의존성

- Node 22.15/24에서 테스트 18개 통과, Vite 빌드 통과. 기존 Vite 보안 경고는 8.3.5 갱신으로 제거했다.
- 독립 리뷰에서 로그인 취소 오류를 INITIAL_SESSION이 지우는 문제를 발견했다. 재현 테스트 실패 확인 후 초기 세션 처리를 수정해 통과했다.
- 실제 DB의 scans 행은 0개다. authenticated SELECT만 허용되며 INSERT/UPDATE/DELETE와 anon SELECT는 차단됨을 확인했다. 데이터는 추가하지 않았다.
- Google 제공자가 비활성 상태라 실제 사용자 로그인과 A/B 데이터 검증은 수행하지 못했다. 화면은 활성화 경로를 안내한다. 설정 절차와 저장 서버 연동 경계는 README에 기록했다.

GitHub 커넥터는 이슈 #14에 404, 로컬 gh는 미로그인이라 사용자가 붙여준 요구사항과 저장소 계약을 기준으로 한다. 기존 미커밋 작업은 유지한다. 원격 DB 변경·실제 메일 입력·커밋·푸시는 하지 않는다.
