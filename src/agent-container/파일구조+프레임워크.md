# 파일구조와 프레임워크

작성일: 2026-11-06

혼자 구현하는 1차 버전을 기준으로 한다. 최상위 구성은 `control-dashboard/`와 `agent-container/`로 분리하고, 제어 기능을 담당하는 폴더 이름은 `backend/`로 통일한다. 이 문서는 구현 계획이며, 아래 파일과 서비스가 이미 구현되었다는 의미는 아니다.

## 1. 사용할 기술

| 구분 | 사용할 기술 | 역할 |
|---|---|---|
| 대시보드 화면 | HTML + CSS + 기본 JavaScript | LLM 설정, 메일 입력, 실행·중지, 로그·결과 표시 |
| 제어 백엔드 | FastAPI + Python | API, 컨테이너 관리, LLM 연결, 증거 수집·판정 |
| 에이전트 | Python | 모델 응답 처리, 도구 실행, 실행 로그 출력 |
| 테스트 수신 서버 | FastAPI + Python | 테스트 요청 수신과 증거 기록 |
| 실행 환경 | Docker + Docker Compose | 서비스 실행과 네트워크 구성 |

- FastAPI가 화면 파일과 API를 함께 제공한다.
- 화면은 JavaScript의 `fetch()`로 API를 호출한다.
- 분석 중에는 주기적으로 진행 상태와 새 로그를 조회하고, 종료되면 조회를 멈춘다.
- React·Vite와 별도 프론트 빌드 과정은 사용하지 않는다.
- 에이전트는 Python으로 실행 루프와 도구 호출 처리를 직접 구현한다.

## 2. 최상위 구조

| 경로 | 역할 |
|---|---|
| `control-dashboard/` | 화면, 제어 백엔드, 테스트 수신 서버 코드 |
| `agent-container/` | 작업 컨테이너에서 실행할 에이전트와 도구 코드 |
| `compose.yaml` | 제어 서비스·수신 서버·네트워크 구성 |
| `README.md` | 설치와 실행 방법 |
| `docs/` | 설계 문서, 요청·응답·이벤트 규격 |
| `tests/` | 정상·인젝션 메일, 예상 결과, 통합 테스트 |
| `data/runs/` | 실행별 로그·증거·결과 저장 |
| `.gitignore` | 실행 데이터·키·임시 파일의 Git 등록 방지 |
| `파일구조+프레임워크.md` | 프레임워크와 파일별 책임을 정리한 이 문서 |

폴더 구분과 실행 단위는 별개다. 대시보드 화면과 제어 백엔드는 하나의 제어 서비스로 제공하고, 에이전트와 테스트 수신 서버는 각각 별도 컨테이너로 실행한다.

## 3. control-dashboard/

| 내부 경로 | 역할 |
|---|---|
| `frontend/index.html` | 설정·메일 입력·로그·결과 화면 |
| `frontend/style.css` | 화면 스타일 |
| `frontend/app.js` | 버튼 동작, API 호출, 상태·로그 갱신 |
| `backend/main.py` | 제어 서비스 시작과 화면 제공 |
| `backend/api.py` | 대시보드용 설정·실행·중지·결과 API |
| `backend/worker_api.py` | 작업 컨테이너 전용 LLM 요청 창구 |
| `backend/runs.py` | 실행 상태·토큰·한도 관리, 작업 컨테이너 생성·정리 |
| `backend/llm.py` | Ollama 연결. OpenRouter·호환 API는 추가 구현 |
| `backend/evidence.py` | 로그·수신 증거 수집, 파일 검증, 결과 보관 |
| `backend/rules.py` | 이상 행동 판정 규칙 |
| `receiver/main.py` | 테스트 요청 수신과 수신 기록 출력 |
| `receiver/Dockerfile` | 수신 서버 이미지 정의 |
| `Dockerfile` | 제어 서비스 이미지 정의 |
| `requirements.txt` | 제어 서비스·수신 서버의 Python 의존성 |

### 화면과 제어 백엔드

- 대시보드에서 Ollama 주소·모델명 또는 외부 API 연결 정보를 설정하고, 분석할 메일을 입력한다.
- 연결 확인, 분석 실행·중지, 진행 상태·모델 응답·도구 호출·최종 결과 확인 기능을 제공한다.
- 공급자 API 키와 연결 설정 원본은 제어 백엔드가 보관한다.
- 실행별 작업 컨테이너의 생성·중지·정리와 실행 한도 적용은 제어 백엔드가 담당한다.
- 로그·결과는 작업 컨테이너 밖의 `data/runs/`에 보관한다. 제어 서비스를 컨테이너로 실행할 때도 해당 저장 경로를 영속화한다.
- 메일 본문과 모델 출력은 일반 텍스트로 표시하고 외부 리소스를 자동으로 불러오지 않는다.

### API 접근 분리

`api.py`와 `worker_api.py`는 파일만 나누는 것이 아니라, 실행할 때도 리스너와 접근 경로를 분리한다. 작업 컨테이너에는 LLM 요청 창구만 노출하고 대시보드의 관리 API에는 접근하지 못하도록 구성한다. 실제 접근 제한은 네트워크 구성과 함께 검증한다.

### 테스트 수신 서버

- `receiver/`는 코드상 제어 대시보드 폴더에 포함하지만 별도 컨테이너로 실행한다.
- 수신 서버는 internal 작업 네트워크에 연결하고, 에이전트의 `fetch_url`은 등록된 수신 서버의 내부 주소로 요청한다.
- 제어 백엔드는 수신 기록을 가져와 `source=receiver`와 해당 `run_id`를 연결해 보관한다.
- 수신 증거를 검증·보관하기 전에 해당 기록을 정리하지 않는다.
- 1차에서는 `control-dashboard/requirements.txt`를 제어 서비스와 수신 서버 빌드에 함께 사용한다. 두 Dockerfile의 빌드 컨텍스트는 `control-dashboard/`로 맞춘다.

## 4. agent-container/

| 내부 경로 | 역할 |
|---|---|
| `main.py` | 작업 입력을 받고 에이전트 시작 |
| `agent.py` | LLM 요청 → 응답 처리 → 도구 실행 반복 |
| `tools.py` | 메일 읽기·요약 저장·실험 도구 구현 |
| `events.py` | 도구 요청·실행 보고를 JSONL로 출력 |
| `Dockerfile` | 에이전트 이미지 정의 |
| `requirements.txt` | 에이전트의 Python 의존성 |

- 에이전트는 제어 백엔드에 추론을 요청하고, 공급자 API 키를 직접 보관하지 않는다.
- 대시보드와 제어 백엔드는 작업 컨테이너에 포함하지 않는다.
- 도구는 처음에 `tools.py` 하나로 시작하고, 규모가 커지면 `tools/` 폴더로 나눈다.
- 모델의 도구 요청과 실제 실행 보고를 구분한다. 도구 요청의 처리 결과는 차단·모의 실행·실제 실행으로 구분해 기록한다.
- 작업 컨테이너의 실행 보고와 외부에서 확인한 효과 증거를 구분한다. 실제 수신 여부는 receiver 기록으로, 파일 변경은 외부 검증으로 확인한다.

## 5. 실행 흐름

1. 사용자가 대시보드에서 LLM 연결 정보를 설정하고 연결을 확인한다.
2. 메일을 입력하고 분석 실행을 누른다.
3. 제어 백엔드가 `run_id`를 발급하고 실행 한도·토큰·작업 컨테이너를 준비한다.
4. 에이전트가 제어 백엔드의 LLM 창구를 이용해 추론을 요청하고 도구를 실행한다.
5. 제어 백엔드가 로그·수신 증거를 수집하고 대시보드에 상태를 제공한다.
6. 작업을 종료한 뒤 파일과 수신 증거를 검증하고 결과를 보관한다.
7. 보관이 완료되면 작업 컨테이너와 실행별 임시 자원을 정리한다.

제어 대시보드는 계속 유지하며 분석마다 작업 컨테이너를 생성·정리한다. 대시보드에서 중지하더라도 증거 검증·보관 후 정리하는 순서를 유지한다. 이전 실행 결과는 작업 컨테이너의 수명과 무관하게 확인할 수 있어야 한다.

## 6. 구현 범위와 확장 원칙

- 파일 구조는 1차 구현 기준이며, 세부 클래스와 보조 파일은 구현하면서 필요할 때 추가한다.
- 공통 요청·응답·이벤트 규격은 `docs/`에서 정리하고 테스트에서 일관성을 확인한다.
- `compose.yaml`은 기본 서비스와 네트워크를 구성하고, 실행별 작업 컨테이너는 제어 백엔드가 관리한다.
- Tracee 등 외부 감시기 연동은 후속 단계에서 추가한다. 현재 파일 목록에 감시기 구현이 포함되었다고 가정하지 않는다.
- 별도 데이터베이스는 이 문서에서 확정하지 않는다. 1차 실행 로그와 결과는 실행별 파일 저장을 기준으로 한다.
