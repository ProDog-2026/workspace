# 이슈 #35 — 정적 탐지기 외부 평가와 점수 계약

2026-11-02 · 윤주혁
[이슈 #35](https://github.com/ProDog-2026/workspace/issues/35) · [PR #48](https://github.com/ProDog-2026/workspace/pull/48) (리뷰 대기) · 수치 원본 [`docs/dataset/issue-35-external-evaluation.md`](../docs/dataset/issue-35-external-evaluation.md)

임계값을 개발셋에서 맞췄으니 한 번도 안 본 데이터에서는 어떻게 되는지 확인하는 게 이 이슈였다.
영어는 InjecAgent Gmail 공격 124건, 한국어는 KoPI-Bench에서 메일로 쓸 만한 2,806건을 골라
넣었다. 둘 다 학습·검증·임계값 선택에 안 쓴 데이터다. 겸해서 탐지 확률을 대시보드 점수로
넘기는 규칙도 확정했다.

결과는 반반이다. 영어 공격은 124건 전부 잡았다. 한국어는 공격도 다 잡았는데 정상도 다 잡아서,
사실상 "전부 의심" 상태다.

## 쓸 수 있는 것과 못 쓰는 것

쓸 수 있다.

- 영어 공격 탐지. 외부 공격 124건에서 미탐 0건.
- 점수 계약. 식, 출처, 실패 처리까지 코드와 문서에 다 반영됐다.
- 영어 정상 오탐률. 그룹 분리된 test ham 33,761건에서 0.25%.

못 쓴다.

- 한국어 메일의 `safe` 판정. 정상 1,234건 중 `safe`가 0건이었다.
- 한국어 정상 메일 데모. 넣는 대로 다 노랗게, 빨갛게 뜬다.

## 숫자

운영 탐지기는 TF 계열과 #31 Transformer 중 더 높은 판정을 고르는 하나의 로직이다. 그래서
모델별로 쪼개 보지 않고 아래 최종 판정으로 본다. `suspicious` 이상이면 "검토 대상"으로 셌다.

| 평가셋 | safe | suspicious | danger | |
| --- | ---: | ---: | ---: | --- |
| InjecAgent 공격 124건 | 0 | 47 | 77 | 재현율 100%, 미탐 0% |
| KoPI-Bench 공격 1,572건 | 0 | 1,026 | 546 | 재현율 100%, 미탐 0% |
| KoPI-Bench 정상 1,234건 | 0 | 818 | 416 | 오탐 100% |

한국어 쪽은 공격 재현율 100%, 정상 오탐률 100%다. 둘이 같다는 건 변별력이 0이라는 뜻이다.
임계값을 올려 `danger`만 탐지로 봐도 34.73% / 33.71%로 여전히 붙어 있다. 영어는 공격만 있는
데이터라 오탐률 자체를 계산할 수 없다. 검토 게이트 기준 한국어 정밀도는 56.02%.

전에 돌던 InjecAgent 미탐률 15.3%(19/124)는 `suspicious`를 0.338996으로 쓸 때 숫자다. 지금
운영 경계는 0.05다. 모델이 좋아져서 0%가 된 게 아니라 경계를 내려서 그렇다. 두 숫자를 개선
전후로 섞어 쓰면 안 된다.

이번 평가로 임계값이나 가중치는 안 건드렸다. 건드리면 이 데이터가 더 이상 외부 테스트가
아니게 된다.

## 점수 계약

```
static_score = round(prompt_injection_probability * 100)
```

표시용 백분율이다. 판정은 이미 탐지기 쪽에서 끝나 있으니 대시보드가 이 점수로 기준선을 다시
그으면 안 된다. `verdict`를 그대로 쓰면 된다.

- 결합 판정일 때는 최종 판정을 낸 쪽 점수를 쓴다. 둘이 같은 판정이면 더 높은 점수.
- 두 모델 확률은 보정 기준이 달라서 숫자끼리 비교하지 않는다. 단계(`safe` < `suspicious` < `danger`)만 비교하고, 누가 올렸는지는 `decided_by`에 남는다.
- R01~R07은 데모에서 근거 문장만 찾는다. 점수에도 판정에도 안 들어간다.
- 탐지 실패면 `status="failed"`이고 `verdict`·`probability`·`static_score`가 전부 `null`이다. 실패가 `safe`로 바뀌는 길은 없게 해뒀다. 스키마에서 NULL을 허용해야 한다.
- 탐지기를 아예 안 붙인 상태는 `null`이 아니라 `scan_mail()`이 `None`을 돌려준다. `failed`와 다른 상태다.

현재 임계값은 TF 계열 `0.05` / `0.414419`, Transformer `0.939322` / `0.942692`다. 구현은
`src/gmail/src/prodog_gmail/scan.py`, 계약 문장은 `arch/INTEGRATION.md`에 있다.

## 한국어가 왜 이러나

KoPI-Bench는 영어 자료를 한국어로 번역한 데이터고 실제 국내 메일이 아니다. 그래서 "한국어는
전부 오탐"보다 "이 번역체 분포에서 변별력이 0"이 정확한 표현이다. 그래도 통과 기준으로 쓸 수
없다는 결론은 같다.

원인 쪽을 보면, #31 Transformer가 두 평가셋 공격을 모두 `safe`로 분류했다. 영어 Quadrat-IPI로
학습했으니 예상된 결과다. 그래서 최종 판정은 전부 TF 계열에서 결정됐고, #31 적용 전후로 바뀐
판정은 InjecAgent 0건, KoPI-Bench 0건이다. #31을 빼자는 얘기는 아니다. 이 두 외부셋에서 효과가
안 보였을 뿐이고, 인코더를 한국어나 다국어로 바꾸면 달라질 수 있는 부분이다.

이 단독 숫자는 발표에 쓰지 않는다. 이슈 완료 조건이 전후 비교라서 측정했고, "왜 #31이 숫자를
안 바꿨나"를 설명할 때만 쓴다.

### 영어 정상 메일을 더 안 구한 이유

영어 외부 오탐률이 비어 있는 건 맞다. 그런데 공개 영어 ham이 Enron, SpamAssassin, TREC인데 셋
다 이미 phishing-curated 학습 풀에 들어가 있다. 같은 계보를 다시 받아 "외부셋"이라고 부르면
그게 더 틀린 기록이 된다. 영어 정상 오탐은 그룹 분리된 test ham 33,761건의 0.25%로 두고, 공수는
한국어 정상 데이터에 쓰는 게 맞다고 봤다. 사유는 `docs/`에 적어뒀다.

교수님이 영어 외부 오탐도 수치로 보자고 하면 계보가 안 겹치는 걸 찾아야 하는데, 현실적 후보가
Avocado IT 정도고 라이선스 신청이 필요하다.

## 각자 볼 것

**이지훈** (#14, #38) — `static_score`로 색 정하지 말고 `verdict` 쓰면 된다. 점수가 `null`로 오는
경우가 두 가지(검사 실패, 탐지기 미설정)라서 UI에서 구분이 필요하다.

**김서진** (#12, #37) — `scans`를 테이블로 갈지 뷰로 갈지 정할 때 `static_score` NULL 허용과
`status` 보존만 챙기면 된다. `arch/SUPABASE_TABLE.md`에 정의돼 있다.

**박한빈·이지훈** (#36) — 이게 좀 중요하다. `suspicious`가 2차 판단으로 넘어오는 구조인데
한국어는 거의 전량이 넘어온다. "의심 메일 일부"가 아니라 "사실상 다"로 보고 로컬 LLM 처리량을
다시 잡아야 한다.

**심재훈** — #35는 평가·계약 이슈라 닫아도 되지만 한국어 오탐은 열린 결함이다. 후속 이슈 2건을
만들지, 발표 데모를 영어로 갈지 결정이 필요하다.

**다같이** — `safe`는 안전하다는 뜻이 아니라 현재 분석 범위에서 못 잡았다는 뜻이다. 발표 문구에서
"안전"으로 쓰면 곤란하다. 데모는 영어 공격 + 영어 정상 조합이 안전하다. 한국어를 꼭 넣어야 하면
한계를 먼저 말하고, 탐지 성능이 아니라 파이프라인 흐름을 보여주는 쪽으로 구성한다.

후속 이슈로 뺄 것.

- 한국어 정상 hard negative 확보. 결제·청구·영수증·보안 안내·업무 요청 같은 것들. 같은 정상 메일에 공격 문장만 넣은 paired로 공격을 구성하고, KoPI-Bench는 출처·템플릿 계보 단위로 잘라 개발셋으로 전환한다.
- 한국어/다국어 인코더 비교. 같은 분할, 같은 오탐 예산에서 현재 BERT-tiny와 붙여본다. (#31)
- 프론트엔드 근거 표시 교체. `rules.js`의 R01~R07은 은닉 기법 정규식이고 정적 탐지기는 확률
  하나와 3단계만 반환한다. 데모 화면·목업의 R01~R07 근거 표시를 모델 출력으로 바꾸되, 모델이
  탐지 유형·문장을 반환하도록 확장하는 건 또 별개다. 분리 전까지는 데모용임을 화면에 명시한다.

실제 서비스 형태의 합성 `.eml` 정상·공격 쌍은 최종 테스트용으로 끝까지 아껴둔다. 임계값 조정에
쓰면 최종 평가가 없어진다. 문맥 분석의 한국어 평가는 [#36](https://github.com/ProDog-2026/workspace/issues/36)과 연결한다.
