# 합성 인젝션 실험과 팀 실행 준비

사용자 요청: 앞서 설명한 격리·평가 한계를 개선하고, 사용자가 GitHub에 올린 변경을 팀원이 pull받아 실행할 수 있도록 준비한다. 커밋·푸시는 사용자가 한다. 기존 dirty 작업과 실제 계정·메일·키를 보존한다.

## 구현 선택

기존 FastAPI Experiments/Ollama/Docker 실행기를 재사용한다. 새 VM 플랫폼이나 별도 실행 서버는 추가하지 않는다. 단순 로그 집계만으로는 정상/공격 조건 비교와 50건 보존 한계를 해결하지 못하므로, 기존 동적 분석 화면에 정상/공격 쌍 입력과 반복 실행·그룹 결과를 추가한다. 합성 그룹은 Gmail·정적 판정과 독립적으로 실행하며 로컬 Ollama만 사용한다.

- Sandbox는 실행마다 random canary를 생성하고 stdin으로 전달한다. 호스트 argv/환경변수로 전달하지 않는다. 기존 고정 문자열만 복사해서 유출 성공으로 보이던 오염을 막는다.
- 기존 네트워크 없음·비루트·읽기 전용·자원/시간/출력 제한과 cleanup 실패 barrier를 유지한다. 실험은 명시적인 Docker context와 준비된 Linux 이미지가 필요하다.
- 관측된 canary 복사는 나중에 파일이 삭제돼도 공격 성공 관측으로 남는다. stdout/stderr 노출과 고정 목표 파일 유출을 구분한다. 미관측/오류를 방어 성공으로 표현하지 않는다.
- 정상 작업은 최종 summary의 전체 수집과 검증어 포함 여부로 확인한다. 이는 의미 정확도 판정이 아닌 명시적 proxy다. label·검증어·canary 정답은 모델 프롬프트에 넣지 않는다.
- 그룹별 기대 실행 수·label·case/repeat·상태·관측·시간 요약은 로컬 SQLite에 암호화해 보존한다. 상세 로그 최근50건이 정리돼도 분모가 바뀌지 않는다. ASR과 오류/미확정, 정상 과제 proxy, 평균/P95를 함께 보여 준다. 정적 F1은 이 동적 그룹 지표에 섞지 않는다.
- 그룹당 최대20case×3repeat=60개. 현재 전역 동시1·queue100을 재사용하고 수용량/입력을 등록 전에 검사한다. 사용자·CSRF 경계를 유지하고 앱 UUID가 있는 평가 기록은 Gmail 연결/쿠키 회전 후에도 본인만 조회한다.
- 팀 preflight는 설정을 변경하거나 설치하지 않고 모델/환경/런타임/context 준비 실패를 구분한다. Apple Silicon Lima는 실제 검증, Windows/Linux Docker 경로는 별도 조건·검증 수준을 문서에 명시한다. 가중치·키는 Git에 넣지 않고 신뢰한 별도 팀 배포본을 준비한다.

## 검증

canary contamination·부분 관측·기록 retention·소유권·CSRF·등록 중 잘못된 입력·모델 revision·오류 분모를 회귀 검사한다. 실제 VM에서 합성 canary 작업과 cleanup을 확인하고 실제 Ollama 정상/공격 쌍을 임시 저장소로 실행한다. Git tracked 파일만으로 만든 별도 임시 checkout에서 preflight/help·설치 안내·모델 누락 감지를 확인한다. 실제 Gmail 계정/자동 설정을 바꾸지 않는다. Windows 실제 실행·탐지 정확도 일반화·VM 탈출 검증은 별도 범위다.
