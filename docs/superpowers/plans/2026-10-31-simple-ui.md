# 간단한 메일 테스트 화면

요청: 홈페이지 문구를 줄이고 어려운 합성 평가 용어·복잡한 입력을 간단하게 바꾼다.
기본 흐름: 메일 한 개 입력 → 테스트 시작 → 결과/중지. 입력은 로컬 Ollama로만 보낸다.
두 메일 비교·상세 통계·원문 로그·환경 정보는 필요한 경우만 펼친다.
기존 계정/CSRF/VM 제한, 오류·미관측 구분, 삭제 확인과 지난13개 수정은 유지한다.
실제 메일/원격 DB/키는 변경하지 않으며 커밋·푸시도 하지 않는다.

- [x] 단일 메일 테스트 입력/실행/결과 + 기존 로그/취소/다운로드 연결
- [x] 기존 일곱 개 메뉴·이름·순서를 유지하며 각 화면 문구 정리
- [x] 비교 기능의 쉬운 표현과 상세 통계 접기
- [x] 신규 수동 테스트를 앱 UUID에 귀속하고 재연결 후 접근·로그아웃 중지 검증
- [x] 전체 검사/빌드 및 실제 브라우저에서 기본 화면·접기·반응형 확인

기존 POST /api/experiments와 ExperimentInput을 재사용한다. 자동 Gmail 파이프라인과
Supabase 저장 계약은 바꾸지 않는다. 수동 테스트에서 정적 판정이나 탐지 정확도를 꾸미지 않는다.

## 검증 결과

- 프론트 90 passed, Vite build 통과. 기존 번들 크기 경고는 유지된다.
- 백엔드 518 passed / 12 opt-in skipped. Ruff와 diff 공백 검사 통과.
- 실제 브라우저에서 소개/설정/기본 테스트, 옵션·비교 접기, 기존 합성 결과 조회와 결과 초점 이동 확인.
- 390px 화면에서 문서 폭 390px으로 가로 넘침 없이 입력·메뉴·실행 버튼 확인 후 원래 화면 크기 복원.
- 일반 예시 제출은 기존 실행 중 작업 때문에 409로 거절됐고 해당 오류가 표시됐다. 새 모델 실행 완료는 검증하지 않았다.
- 기존 작업 보존을 위해 실제 백엔드를 재시작하지 않았다. 새 수동 기록의 UUID 귀속은 재시작 후 적용된다.
- 커밋·푸시·PR 생성·원격 DB 변경 없이 기존 수정과 잠금 파일을 유지했다.

## 요청 범위 정정

사용자의 요청은 각 항목 안의 가독성 개선이다. 임의로 줄였던 메뉴와 이름·순서를 기존 일곱 개로 복원하고, 설정으로 옮겼던 추가 도구 링크는 제거했다. 페이지 제목과 안내 문서도 기존 메뉴 이름에 맞췄다.
