# Quadrat-IPI 기반 Transformer

## 목적

기존 TF 계열 정적 탐지기와 별도로 문맥 기반 간접 프롬프트 인젝션을 탐지하는 Transformer를
학습한다. 실행 시 두 모델이 같은 메일을 독립적으로 판정하고 더 높은 판정 단계를 최종 결과로
사용한다.

## 데이터 출처와 사용 범위

- 데이터셋: [Quadrat-IPI](https://huggingface.co/datasets/mihailgribov/quadrat-ipi)
- 고정 버전: `v1.0.2`
- 라이선스: ODC-BY 1.0
- 사용 파일: `data/negatives.jsonl`, `data/positives.jsonl`
- 필터: `host_type == "email"`
- 대상 언어: 영어
- 이메일 행: 정상 21,000건, 인젝션 6,160건

Quadrat의 `clean`과 `injected`는 원래 학습/시험 분할이 아니라 서로 다른 평가 모집단이다.
따라서 이 구현은 `host_source + host_id`를 그룹 키로 삼아 80% 학습, 20% 검증으로 새로
분리한다. 같은 원본 메일에서 파생된 정상·인젝션 행은 항상 같은 쪽에 들어간다.

학습에는 그룹 분리 후 인젝션 4,935건 전량과, 결정적 해시로 고른 정상 4,935건을 사용했다.
검증 임계값 산정에는 정상 1,000건과 인젝션 1,000건을 사용했다. 이 검증 결과는 같은 Quadrat
데이터에서 나온 값이므로 독립 외부 성능으로 해석하면 안 된다.

원본 데이터는 `src/detector/data/vendor/quadrat-ipi-v1.0.2/`, 학습 가중치는
`src/detector/models/quadrat-transformer/`에 저장한다. 원본 데이터와 운영 가중치는 모두
Git에서 제외한다. 운영 가중치는
[Notion 모델 파일 페이지](https://app.notion.com/p/40714dd1c3c48153b351f8fd6c01855d)에서 내려받는다.

## 모델과 입력 처리

- 기반 모델: `prajjwal1/bert-tiny` (BERT 2층, hidden size 128)
- 학습: CPU, 1 epoch, batch 32, learning rate `3e-5`
- 입력 길이: 모델 상한인 512 token. 설정 파일에 적지 않고 추론 때
  `config.max_position_embeddings`에서 읽는다
- 긴 메일: 토크나이저가 512 token 조각, 64 token 중첩으로 나눈다. 조각 중 최대 확률을 메일
  점수로 사용한다. 중첩 64는 한국어 코퍼스 공격 문구 136종의 최대 길이가 41 token이라
  어떤 문구도 조각 경계에서 쪼개지지 않는 값으로 잡았다
- 학습 인젝션: `inj_span`을 중심으로 1,000자를 잘라 실제 공격 문구가 입력에 포함되게 함.
  이 1,000자는 학습 샘플 크기이고(`--training-window-chars`), 추론 조각 나누기와 무관하다
- 실행 의존성: PyTorch와 Transformers만 사용하며 LLM API는 호출하지 않음

### 2026-11-20 정정: 글자/토큰 단위 불일치

2026-11-20까지 추론은 입력을 1,000**자** 단위로 나누고 절단은 256**토큰**으로 걸었다. 둘을
맞춰주는 코드가 없어서 조각 뒷부분이 조용히 버려졌다(이슈 [#86](https://github.com/ProDog-2026/workspace/issues/86)).
실제 영어 메일 118건에서 1,000자 창 중 모델에 들어간 비율은 중앙값 84%, 최악 51%였고,
1,000자가 256토큰에 온전히 들어간 메일은 118건 중 18건뿐이었다.

학습 쪽도 같이 잘렸다. 공격 학습 샘플 800건 중 62%, 정상 800건 중 43%가 256토큰에서 절단됐다.
아래 2026-10-26 수치는 그 상태에서 측정한 값이다.

### 조각 방식 변경 후 임계값 재보정

조각 방식이 바뀌면 점수 분포가 달라지므로 임계값을 다시 골랐다. **재보정은 추론만 하면 되므로
재학습이 필요 없다.** 검증 2,000건(정상 1,000 / 인젝션 1,000) 기준이다.

| 구성 | ROC AUC | suspicious | danger |
| --- | ---: | --- | --- |
| 256 학습 + 구방식 추론 (2026-10-26) | 0.997089 | 98.7% @ FPR 4.8% | 96.0% @ 0.2% |
| 256 학습 + 토큰 조각, 기존 임계값 | 0.995963 | 95.7% @ 2.1% | 87.5% @ 0.1% |
| **256 학습 + 토큰 조각, 재보정 (채택)** | **0.995963** | **97.5% @ 4.8%** | **91.4% @ 0.2%** |
| 512 재학습 + 토큰 조각 | 0.994408 | 96.6% @ 4.5% | 90.4% @ 0.2% |

운영 임계값을 `0.939322`/`0.942692`에서 **`0.937523`/`0.941672`**로 바꿨다. 가중치는 그대로다.

### 512 재학습을 채택하지 않은 이유

조각이 최대 512토큰이 됐으니 학습도 512로 맞추면 나아질 것으로 보고 재학습했는데, ROC AUC가
`0.994408`로 오히려 내려갔다. 길이 불일치는 원인이 아니었다.

원인은 길이가 아니라 **텍스트 구성**으로 보인다. 학습 샘플은 `_centered_window`로 공격 문구를
한가운데 둔 1,000자 조각인데, 추론은 메일 전체를 조각낸다. 공격이 가운데 박힌 짧은 조각으로
배우고 실전에서는 공격 위치를 모르는 긴 조각을 받는 셈이다. 구방식이 가장 높았던 것은 추론도
같이 잘려서 우연히 학습 분포와 맞아떨어졌기 때문으로 보인다.

이 가설대로라면 `_training_text`가 창을 자르지 않고 전체 텍스트를 쓰도록 바꿔야 한다. 이슈
#86 범위 밖이므로 후속 과제로 둔다.

## 2026-10-26 검증 결과 (절단 상태, 기록용)

| 판정 기준 | 임계값 | 재현율 | 정밀도 | F1 | 정상 오탐률 |
| --- | ---: | ---: | ---: | ---: | ---: |
| suspicious 이상 | 0.939322 | 98.7% | 95.36% | 97.00% | 4.8% |
| danger | 0.942692 | 96.0% | 99.79% | 97.86% | 0.2% |

ROC AUC는 `0.997089`다. 전체 수치는
`src/detector/reports/quadrat-transformer-metrics.json`에 기록한다.

기존 수동 30건(`manual-evaluation-2026-10-12.jsonl`)을 다시 검사하면 TF 계열 모델과 결합
모델 모두 20/30(66.7%)이었다. Transformer 단독은 15/30이었고, 짧은 직접 명령 위주인 이
표본에서는 결합 결과를 추가로 개선하지 못했다. 반면 Quadrat 검증 행 중 기존 모델이 `safe`로
놓친 간접 인젝션을 Transformer가 `danger`로 올리는 사례는 확인했다.

## 한계

- 현재 학습·검증 데이터는 영어뿐이며 한국어 성능은 측정하지 않았다.
- 임계값도 Quadrat 내부 검증 표본에서 정했으므로 별도 외부 이메일 데이터로 다시 평가해야 한다.
- 짧고 노골적인 직접 명령은 Transformer가 놓칠 수 있다. 이 경우 기존 TF 계열 모델의 판정이
  최종 결과에 반영된다.
- 두 모델의 확률은 보정 방식이 달라 확률 숫자의 최댓값이 아니라 판정 단계의 최댓값을 사용한다.
