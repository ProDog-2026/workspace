# 프롬프트 인젝션 탐지 모델 데이터셋

담당자는 윤주혁이며, 목표 마감일은 2026-10-09였다. 기존 `Prodog-Sast` 모델을
`src/detector/`로 옮기면서 학습 데이터, 분리 기준, 사용 범위와 실측 결과를 정리했다.

## 학습 데이터

### Microsoft LLMail-Inject

- 출처: <https://huggingface.co/datasets/microsoft/llmail-inject-challenge>
- 확인 수준: 데이터셋 카드와 배포 파일을 직접 확인함
- 라이선스: MIT
- 사용 필드: 공격 메일 묶음과 같은 시나리오의 정상 메일 묶음
- 사용량: 총 10,000쌍 중 해시 분리한 학습용 8,044쌍(16,088건, 중복 공격 문구를 묶은 8,017그룹)
- 외부 평가: 학습에서 제외한 1,956쌍(3,912건)

`attack_prompt`의 SHA-256 해시를 5로 나눈 값으로 분할해 같은 공격 문구가 학습과 외부 평가에
동시에 들어가지 않게 했다. 원본 ZIP과 가공 JSONL은 `src/detector/data/`에 로컬로만 두며 Git에
올리지 않는다.

### Paired Email Dataset

- 출처: <https://github.com/compass-group-tue/prompt_injections_so_back>
- 확인 수준: 연구 저장소의 데이터 설명과 배포 파일을 직접 확인함. 논문 본문은 미확인.
- 규모: 4,200개 시나리오 쌍, 정상·공격 총 8,400건
- 사용 필드: 각 쌍의 `external_content`만 사용
- 제외 필드: `user_prompt`는 모델 입력에서 제외
- 라이선스: 저장소에 명시적 라이선스 파일이 없어 `TBD`

명시적 라이선스가 확인되기 전에는 원본 데이터와 여기서 생성한 모델을 외부에 재배포하지 않고
팀 내부 연구·검증에만 사용한다.

## 전체 학습 구성

두 데이터셋에서 총 24,488건, 12,217개 그룹을 구성했다. 같은 시나리오의 정상·공격 쌍은 같은
`group_id`를 가지며 그룹 단위로 다음처럼 분리했다.

| 분할 | 샘플 | 그룹 | 용도 |
| --- | ---: | ---: | --- |
| train | 17,138 | 8,551 | TF-IDF와 분류기 학습 |
| validation | 3,672 | 1,833 | 임계값 선택 |
| test | 3,678 | 1,833 | 내부 최종 평가 |

train/validation/test 사이 그룹 중복은 0건이다. validation 정상 오탐률을 2% 이하로 제한하면서
공격 재현율이 가장 높은 임계값 `0.08877245225083939`를 선택했다.

## 모델 입력과 특징

- 공통 입력: 제목, 발신자, plain 본문, HTML 원문, HTML에서 추출한 텍스트
- `.eml` 직접 검사는 수신자와 Reply-To 헤더도 입력에 포함한다.
- 단어 특징: 1~2-gram TF-IDF, 최대 120,000개
- 문자 특징: 3~5-gram TF-IDF, 최대 160,000개
- 분류기: class-weighted `SGDClassifier(loss="log_loss")`
- 학습 라이브러리: scikit-learn 1.6.0
- 출력: 인젝션 확률, 의심·위험 임계값, `safe`·`suspicious`·`danger`

위험 임계값 `0.08877245225083939`는 validation 정상 메일 오탐률을 2% 이하로 제한하면서
공격 재현율이 가장 높은 값이다. 임시 의심 임계값 `0.05`를 검증한 뒤, 정상 validation 점수의
95백분위인 `0.0400186634741522`로 조정했다. 이 값은 위험을 포함해 정상 메일 약 5%만 검토
대상으로 두기 위한 운영 기준이다. 세 단계는 별도로 학습한 3개 클래스가 아니라 하나의 이진
모델 점수를 두 임계값으로 나눈 위험 구간이다.

Gmail 수집 API의 `subject`, `sender`, `text_plain`, `text_html`을 메모리에서 변환한다. 수집 계약에
`reply_to`가 없으므로 Gmail 연동에서는 Reply-To를 사용하지 않고, `.eml` 직접 검사에서만 분석한다.
실제 메일 원문과 변환 결과는 저장하지 않는다. `warnings`가 있거나 `truncated`가 참이면 모델
판정과 별도로 “수집 불완전”을 유지한다.

## 포함된 공격 유형

- 기존 지시 무시와 새 역할 부여
- 메일 전송 등 도구 호출 유도
- 다른 메일·내부 정보의 외부 전송 유도
- 시스템/사용자 구분자와 가짜 지시 블록 삽입
- 공백·기호·반복어를 이용한 난독화
- 정상적인 권한 요청처럼 보이는 문맥·권위 조작

샘플은 공개 연구 데이터 또는 합성 데이터이며 실제 사용자 메일은 포함하지 않는다. 공격 자동화나
실제 계정 대상 시험에는 사용하지 않는다.

## 실측 결과

이 문서에서 **내부 test**는 모델 개발용 24,488건을 그룹 단위로 나눌 때 미리 떼어 둔
3,678건을 뜻한다. 학습·validation과 데이터 출처는 같지만 같은 `group_id`는 겹치지 않는다.
**외부 test**는 LLMail 원본에서 해시 기준으로 처음부터 학습·임계값 선택에서 제외한 별도
3,912건이다. 다만 다른 기관의 실사용 메일이 아니라 같은 LLMail 데이터 생성 체계이므로,
여기서 “외부”는 **개발 과정에서 완전히 보지 않은 분할**이라는 뜻이지 현실 분포 검증이라는
뜻은 아니다.

### 그룹 분리 내부 test

| 지표 | 결과 |
| --- | ---: |
| 공격 재현율 | 1.0000 (1,839/1,839) |
| 정밀도 | 0.9808 |
| 정상 오탐률 | 0.0196 (36/1,839) |
| F1 | 0.9903 |
| ROC-AUC | 1.0000(반올림) |

### 분리 보관한 LLMail 외부 평가

| 지표 | 결과 |
| --- | ---: |
| 공격 재현율 | 0.9990 (1,954/1,956) |
| 정밀도 | 1.0000 |
| 정상 오탐률 | 0.0000 (0/1,956) |

상세 결과는 `src/detector/reports/`에 있다. 이 수치는 LLMail과 paired-email 분포에 대한 결과이며
실제 한국어 조직 메일 성능을 보장하지 않는다.

## 현재 제외한 데이터셋

InjecAgent와 BIPIA는 외부 일반화 평가 후보로만 남겼다. 현재 로컬 파일, 학습 데이터, 보고된
평가 결과에는 포함되지 않는다.

## 알려진 한계와 사용 범위

- 한국어 독립 평가셋이 없어 한국어 공격 탐지 성능은 아직 측정하지 않았다.
- 모델은 메일 문자열만 보고 사용자의 실제 위임 범위나 조직 정책을 알지 못한다.
- 이미지, OCR, 첨부파일 내용은 분석하지 않는다.
- 높은 데이터셋 점수를 실제 서비스 성능이나 안전 보장으로 표현하지 않는다.
- 모델 결과만으로 메일을 자동 차단하거나 에이전트의 도구 실행을 허가하지 않는다.
